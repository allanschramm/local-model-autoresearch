# Qwythos v2 MTP at 100k

## Goal

Complete the throughput, coding-10, and Claw full Objective Vector for `Qwythos-9B-v2-MTP-Q4_K_M.gguf` at 100000 context with embedded MTP active.

## Hardware

- NVIDIA 8 GB-class discrete NVIDIA with 8 GB physical VRAM.
- Physical-VRAM limit: 7900 MB.

## Setup

- Runtime: TurboQuant+ `tqp-v0.3.0`, Windows CUDA release.
- Context: 100000.
- KV: `turbo2/turbo2`.
- MTP: `draft-mtp`, `SPEC_DRAFT_N_MAX=2`.
- Batch/ubatch: `32/16`.
- Sampler: temperature `0.6`, top-p `0.95`, top-k `20`, repeat penalty `1.05`.

## Commands

The mutable Baseline was set in `autoresearch/core/config.py`. The complete Trial used:

```powershell
$env:AUTORESEARCH_LLAMA_CPP_ROOT = (Resolve-Path 'llama.cpp-releases\turboquant\tqp-v0.3.0').Path
.\venv\Scripts\python.exe benchmark_search.py --include-coding --no-agentic-quick --agentic-full --desc full-qwythos-v2-mtp-tqp030-100k-turbo2-draft-mtp2-b32
```

For detached operation, stdout and stderr were redirected to a durable local log at process creation.

## Findings

Trial `f0495d54-7e9c-4697-a1df-f5e8bbe751be` completed successfully:

| Metric | Result |
|---|---:|
| Backend bench | 55.4 t/s |
| Coding generation | 70.2 t/s |
| LiveCodeBench | 0.4000 |
| HumanEval+ | 0.8000 |
| MBPP+ | 0.8000 |
| BigCodeBench Hard | 0.1000 |
| Coding composite | 0.5550 |
| Claw full | 0.3333 (5/15) |
| Peak VRAM | 7.7 GB |

The effective server command contained `--spec-type draft-mtp --spec-draft-n-max 2`. Runtime statistics confirmed embedded MTP activity with draft acceptance, rather than flags alone.

## Errors

- Bare `--spec-type mtp` was rejected by this runtime; its accepted token is `draft-mtp`.
- Batch/ubatch `64/32` reached 7910 MB and was rejected by the physical-VRAM gate during BigCodeBench.
- One detached attempt inherited a launcher output pipe that closed early and ended with `[Errno 22] Invalid argument`; durable redirection removed that infrastructure failure without changing the model settings.

## Decisions

- Keep `32/16` for this 100k MTP Fingerprint; it completed below the physical-VRAM gate.
- Preserve rejected infrastructure and VRAM rows in `results.tsv`.
- Do not sweep MTP n=4 until a separate config-only Trial proves it fits the same physical-VRAM limit.
