Peças do sistema

Inferência
Gerar texto com pesos já treinados (congelados). Não atualiza o modelo. Este curso é só inferência.
Motor
Programa que carrega os pesos e gera tokens (ex.: llama-server). Não é o arquivo do modelo.
Modelo
Pesos no disco — tipicamente um arquivo .gguf.
Quant (quantização)
Compressão dos pesos (Q4, Q5, Q8…). Menos bits → menos VRAM; TPS costuma subir. Não é “treinar de novo”.
GGUF
Formato de arquivo de modelo para motores tipo llama.cpp.
Draft / MTP
Arquivo ou trilha auxiliar de especulação (fora do escopo básico de TPS).

Memória e velocidade

VRAM
Memória da GPU. Pesos + KV competem por ela. Dense deve caber na VRAM física neste curso; MoE pode offload (Semana 1 · Dia 3).
RAM
Memória do sistema (CPU). Offload de especialistas MoE pode usar RAM — não é “free speed”.
KV / contexto
Memória do histórico da conversa. Mais -c → mais KV → mais memória.
TPS
Tokens por segundo — métrica de velocidade. Não mede “inteligência”.
Offload
Colocar parte do modelo fora da VRAM (CPU/RAM). Em dense: evitar. Em MoE: ferramenta do Dia 3.
OOM
Out of Memory — VRAM (ou RAM) esgotada. Em denso, corte contexto/KV, remova draft ou escolha GGUF menor; não force spill.

API, agente e amostragem

API local
Servidor HTTP na sua máquina (ex.: 127.0.0.1:18080), em geral compatível com o formato OpenAI.
Harness
Cliente que fala com a API: script, app, agente ou IDE.
Agent Harness
Skills, MCP e guardrails no cliente do agente (Claude Code, Cursor, Codex, …). Semana 2.
Day
Modelo local no trabalho supervisionado de dia — rápido o bastante; menos tokens de assinatura. Semana 1 · Dia 4; aplicação na Semana 2 · Dia 4.
Night
Modelo local em loop sozinho (ex.: issues de madrugada); de manhã: review, teste, abrir PR. Semana 1 · Dia 4; aplicação na Semana 2 · Dia 4.
Skill
Pacote de instruções (SKILL.md) que ensina o agente a seguir um fluxo. Catálogo: skills.sh. Semana 2 · Dia 1.
Skill local vs global
Local = projeto (padrão do skills add). Global = conta do usuário (-g), vale em qualquer projeto.
Amostragem
Escolher a próxima palavra como pedir o próximo prato: freios → cardápio curto → ousadia → sorteio. Semana 1 · Dia 4. Ordem no motor: penalties → top_k → top_p → min_p → temperature → sorteio.
Temperatura (TEMP)
Ousadia do cliente. Maior = mais criativa; menor = mais precisa. 0 ≈ só o favorito.
Top-K (TOP_K)
Só os K pratos do topo. Desligar: 0.
Top-P (TOP_P)
Só até fechar a fatia P da popularidade. Desligar: 1.0.
Min-P (MIN_P)
Nada fraco demais vs o prato #1. Desligar: 0.0.
Penalidades (repeat / presence / frequency)
Freios da mesa. Repetição (REPEAT_PENALTY, off 1.0) = o que acabou de sair; presença (PRESENCE_PENALTY, off 0) = já pediu ≥1 vez; frequência (FREQUENCY_PENALTY, off 0) = quanto mais pediu, mais freio.
MCP
Plug-and-play de utensílios extras pro agente (cozinheiro). O harness já traz ferramentas; MCP adiciona mais (docs, APIs…). Semana 2 · Dia 2. Skill = receita (Semana 2 · Dia 1).
Context7
Utensílio MCP: manual atualizado de bibliotecas (docs por versão). Cursor / Claude Code.
Sandbox (caixa de areia)
Brinca à vontade dentro da borda; fora, o SO impede (arquivos + rede). Claude: Mac/Linux; no Windows só dentro do WSL2. Cursor: Mac/Linux; no Windows melhor com WSL2 — sem WSL2 quase não protege os arquivos do PC. Semana 2 · Dia 3.
Guardrail
Lista da casa + segurança na porta das tools (Allow / Deny / Ask + hooks). Metáfora: boate. Cursor e Claude Code. Semana 2 · Dia 3.
Fadiga de aprovação
Aprovar no reflexo (Enter) sem ler. Motivo dos guardrails.
Allow / Deny / Ask
Permitir sem prompt / bloquear / sempre perguntar. Claude: ordem deny → ask → allow.
Hook (pré / pós)
Script antes (pode bloquear) ou depois (registra / avisa) da tool. Claude PreToolUse/PostToolUse; Cursor preToolUse/postToolUse.
--tools / --allowedTools / --disallowedTools
Claude CLI: lista da sessão / rodar sem perguntar / deny. Não misturar --tools com --allowedTools.
