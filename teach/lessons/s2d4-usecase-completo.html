Day / Night — do harness ao PR

Monte o Agent Harness (skills, MCP, guardrails) e use o modelo local no ritmo do dia: Day supervisionado, Night sozinho nas issues, e de manhã review, teste e PR.

← Dia 3 Guia Glossário

Resultado:
Descrever e simular o fluxo Day → Night → manhã; confirmar skills, MCP e guardrails antes de rodar.

Duração:
30–45 minutos (conceito + checklist + simulação).

Pré-requisito:
Skills, MCP e guardrails. API local ajuda na prática real.

1. O fluxo completo

Day = modelo local no trabalho de dia, com você no volante: rápido o bastante para o que está fazendo; menos tokens de assinatura.

Night = modelo local em loop sozinho (ex.: issues abertas). Você dorme; o agente avança o que der dentro das regras do harness.

De manhã: ler o que mudou, rodar testes, abrir ou atualizar o PR. Sem essa etapa, overnight vira bagunça — não entrega.

  1. Agent Harness no lugar (skills + MCP + Allow/Deny/hooks).
  2. Day: servidor local + harness apontando para a API; trabalho supervisionado.
  3. Night: deixar o agente nas issues (com guardrails ativos).
  4. Manhã: review → teste → PR.

Day e Night aqui são uso — como você trabalha com o modelo.

2. Checklist operacional

Antes de Day ou Night, confirme que o harness está no lugar.

Antes de Day ou Night

  • Skills — pacotes de procedimento no harness (skills do projeto ou globais; ex. cadeia wayfinder → grill-with-docs → to-tickets → implement → code-review).
  • MCP — utensílios plugáveis (docs, grafo, etc.). Confirme que o servidor que você usa aparece no harness. Sem MCP ligado, o agente só inventa texto.
  • Guardrails — Allow / Deny / hooks no harness (listas allow / ask / deny, scripts de hook, Run Mode / lista de permitidos).
  • API local — llama-server (ou LM Studio) com o GGUF que cabe no hardware; harness apontando para a porta local.

Day → Night → manhã

  • Day: issues ou tarefas curtas com você revisando cada passo importante.
  • Night: fila de issues; harness com Deny/hooks ativos; sem “aperte Enter em tudo”.
  • Manhã: diff legível → testes → PR (ou pedido de review humano).

3. Simulador do fluxo

Clique nas três fases nesta ordem. O detalhe muda; no fim a simulação marca completo.

Comece por Day — modelo local, você no volante.

Prática

Simulado

  1. Percorra Day → Night → manhã no simulador acima.
  2. Confirme mentalmente: skills, MCP e guardrails estão ativos no harness que você usa.

Real

  1. Suba a API local e aponte o harness para ela.
  2. Deixe uma ou mais issues para um loop Night (com guardrails ligados).
  3. De manhã: review, teste, abra ou atualize o PR.

Abaixo: caminhos opcionais para estudar por conta. Cada um abre um mundo; nenhum é necessário para o fluxo Day/Night que você acabou de montar.

1. Mais velocidade no mesmo motor (llama.cpp)

Speculative decoding: um draft rápido (em geral um modelo menor, ou heads/draft equivalentes) propõe vários tokens; o modelo alvo verifica em lote. Se aceitar, sobe o TPS sem trocar de motor. MTP é uma forma disso no llama.cpp (heads embutidas no GGUF ou um GGUF assistant/draft separado).

  • Speculative decoding / MTP — formatos · baseline MTP
  • KV quant (-ctk / -ctv) — menos VRAM de histórico em contexto fundo — glossário
  • CUDA Graphs / allocators — otimizações avançadas
  • CPU path (AVX/AMX, NUMA) — guia de CPU

2. Outros motores de inferência

llama.cpp continua o padrão local do dia a dia; estes brilham quando o workload muda.

  • vLLM — serving / throughput multi-usuário. docs.vllm.ai
  • SGLang — prefix reuse / RAG / agentic. sgl-project/sglang
  • OpenVINO GenAI — CPU/iGPU Intel. guia OpenVINO
  • TensorRT-LLM — pico NVIDIA “fix”. NVIDIA/TensorRT-LLM
  • Ollama / MLX — UX simples · Apple Silicon. ollama.com · ml-explore/mlx
  • Colibrì — MoE gigante em streaming. guia Colibrì
  • Mapa — landscape de motores

3. Outros Agent Harnesses

Mesmo contrato (skills, MCP, guardrails, tools) — outro “corpo”.

  • Pi — terminal minimalista + API local. pi.dev
  • Hermes Agent — orquestração multi-tool. NousResearch/hermes-agent
  • OpenCode — TUI open-source, multi-provider. anomalyco/opencode
  • Aider — terminal + git nativo. aider.chat
  • Continue — VS Code / JetBrains. continue.dev
  • Cline / Kilo Code — agent no editor. cline.bot · kilocode.ai
  • goose — CLI self-hosted, model-agnostic. block/goose

4. Meta-harnesses

Orquestram Agent Harnesses: agendam, isolam e fecham o ciclo Night → review → PR.

  • Archon — workflows/DAG em worktrees. archon.diy
  • Case — pipeline com gates de evidência até o PR. workos/case
  • Sandcastle — agentes em sandbox + branch. mattpocock/sandcastle
  • OpenHands Agent Canvas — control center de vários agents. docs.openhands.dev
