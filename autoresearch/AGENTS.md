# `autoresearch/` — Core Autotuning Package

## Purpose
Core codebase containing search strategy optimization logic, llama.cpp server wrappers, API client integrations, and evaluation benchmark harnesses (Nexus, Claw, Coding, SWE-lite agentic coding).

## Ownership
Repository developers.

## Local Contracts
- Do not modify internal evaluation logic or benchmarks under `autoresearch/benchmarks/` without authorization.
- **Upstream-first (see `docs/llamacpp-toolset.md` + `docs/llamacpp-flags-audit.md` + root `AGENTS.md`):** Check `llama.cpp/common/arg.cpp:1424` `add_opt` (`~310` flags) before adding any `ENGINE_*/SAMPLER_*` or gate — `90%` already exists upstream (`fit`/`fit-target`/`load-mode`/`warmup`/`cache-ram`/`kv-unified`/`repack`/`swa-full`/`yarn`/`spec-ngram`/`dry`/`xtc`/`override-tensor`/`cpu-mask`/`poll`); harness is passthrough mapper — forward in `autoresearch/core/llama_runner.py:895 _build_cmd` vs `arg.cpp`. Keep only host/WDDM/thermal/Pareto gates (`common/fit.h:14` assumes unlimited host, so `preflight_host_memory:662` + `SHARED 2048` kill are the keepers).
- `autoresearch/core/config.py` owns the mutable Baseline (`ENGINE_DEFAULTS` / `SAMPLER_DEFAULTS`) and validation. File is **gitignored**; seed from `config.py.example`. Before the first Trial on a model, seed `SAMPLER_DEFAULTS` from `docs/models/<card>.md` Recommended settings for the job (agentic/general vs coding). The ignored `.autoresearch_state.json` stores visited memory only. `TPS_FLOOR` (default 20.0) is the only Trial reject gate for throughput — set per model (MoE on 8GB often needs 15–18).
- Baseline `VRAM_LIMIT_MB` is the single VRAM budget for autoloop preflight and runtime monitoring; there is no CLI override. `resolve_vram_limit_mb` **hard-clamps** to ``physical − PHYSICAL_VRAM_KEEPOUT_MB`` (default 512). Overridable via env `AUTORESEARCH_PHYSICAL_VRAM_KEEPOUT_MB` — read inside `dedicated_vram_kill_ceil` so the preflight clamp and runtime monitor agree (8 GB-class dense @ 65k q4_0 sits ~7.7 GB steady-state; keepout 256 measured safe, peaks 7.4–7.8 GB, no Shared spill). Keep Baseline `NO_MMAP` when it wins TPS. **Anti-Shared:** (1) dedicated keepout + kill dense+MoE; (2) absolute Shared GPU kill (`SHARED_VRAM_LIMIT_MB`, default 2048) — MoE+`NO_MMAP` can hit Shared→pagefile with dedicated still ~4–5 GB; (3) `GGML_CUDA_NO_PINNED=1` on cli/server; (4) TPS `llama-cli` `-c` ≤ `BENCH_CTX_CAP`.
- VRAM preflight estimates main GPU-resident weights + configured `CTX_SIZE` KV + enabled external draft weights + conservative speculative/MTP workspace (`512 + 256 * SPEC_DRAFT_N_MAX` MiB) before server start. **KV:** `gguf_kv_f16_mb` — sliding-window arches (gemma4 SWA) charge `min(ctx, window)` + `key/value_length_swa` (not full-ctx × full dims; that false-rejected some MoE loads @ high ctx). **Exception (workspace):** MoE with `n_cpu_moe > 0` and an external draft file (e.g. `draft-dflash`) counts draft weights only — no flat speculative workspace (false-rejects DFlash on 8 GB-class when measured peaks fit). Embedded MTP (no draft file) and dense targets still use the workspace term. **Exception (free clamp):** MoE with `n_cpu_moe > 0` uses the configured `VRAM_LIMIT_MB` only — does not clamp to `free−headroom` (OS-reserved VRAM false-rejects expert-CPU offload). Dense still uses free-at-start headroom (issue #10). **Operator escape:** `AUTORESEARCH_SKIP_FREE_CLAMP=1` skips the free clamp for dense too (configured budget only). **Runtime VRAM kill (dense + MoE):** dedicated `used > min(VRAM_LIMIT_MB, physical − keepout)` **or** process Shared GPU `> SHARED_VRAM_LIMIT_MB`. **TPS `llama-cli`:** `-c` capped at `BENCH_CTX_CAP` (4096); full Trial CTX only on the monitored server; cli has dedicated + Shared watchdogs. Never raise `VRAM_LIMIT_MB` above physical VRAM to clear a bad estimate.
- Host-memory gate lives in `autoresearch/core/hardware.py` + `preflight_host_memory` in `llama_runner.py`: full GGUF (+ draft + KV), no MoE shrink. Unified headroom `max(6144, 0.20×RAM)` MiB; discrete `max(4096, 0.15×RAM)` (NVIDIA CUDA and AMD ROCm/Radeon). Override `HOST_MEMORY_HEADROOM_MB` / `AUTORESEARCH_HOST_HEADROOM_MB`.
- Do not add hardcoded user or absolute directory paths in the source files.
- Model paths: `resolve_model_file` in `model_arch.py` owns flat + nested (`publisher/model/*.gguf`) lookup; `resolve_model_path` in `llama_runner.py` wraps it (missing → `models_dir/ref` for callers to fail later). Config Baseline keeps basenames (and `draft/...` for drafts).
- Architecture class (MoE vs dense): `autoresearch/core/model_arch.py` reads local GGUF metadata (`expert_count` / `*moe*` arch). No filename heuristics. Model cards must mirror that GGUF truth. Agents query it via `scripts/model_info.py <basename>` (read-only, harness-backed) — never parse the raw `.gguf` or scrape tensor dumps.
- MoE `N_CPU_MOE=None` → `resolve_n_cpu_moe` sets `--n-cpu-moe` to GGUF `block_count` (replaces old `override-tensor .*exps.*=CPU`). Explicit `0` = full GPU; `N>0` = manual.
- GPU/CPU split: `N_GPU_LAYERS` in Baseline (`-1` = Auto, `0` = CPU-only, `N>0` = N layers on GPU) and `NUMA` (`None` / `distribute` / `isolate`) are validated in `validate_config` and surface through autoloop `CORE_PASSTHROUGH` (issue #16). CPU-only Baseline is first-class via `N_GPU_LAYERS=0`.
- **Trial order (hard gate):** GGUF arch classify → resolve `N_CPU_MOE` → VRAM preflight → **host-memory preflight** (full GGUF + KV, no MoE shrink) → TPS floor → eval. MoE `N_CPU_MOE=0` that exceeds physical VRAM is `MODEL_REJECTED` (set `None` for auto offload). Dense never uses expert offload. Host gate rejects oversized unified-RAM loads (`HOST_MEMORY_PREFLIGHT`) before Metal/CUDA start.
- **No autonomous autoloop on user request:** When the user asks for a trial, hill climb, bench, validate, or any tuning/eval action, run the explicit harness (`benchmark_search.py`, `python -m autoresearch.runners.run`) — do **NOT** launch `autoloop.py` / the `/autoresearch` autonomous loop. `autoloop.py` is operator-only; the user starts the background hill-climb themselves.
- **Use the harness, not raw binaries**: Run `benchmark_search.py` (or `autoloop.py` only when the operator starts it) for evaluation. Do not invoke `llama-server` or `llama-bench` directly — the harness resolves paths (supporting both `build-cuda` and `build-cpu`), translates config flags to CLI args, manages server lifecycle, monitors VRAM, and logs results. **Claw/agentic loop:** merge `reasoning_content` when `content` is empty (same as coding-10) and pass `max_tokens≥4096` for agentic tiers — thinking models otherwise get blank graders + mid-loop HTTP 400; 1.5-class CoT still exhausts 2048 mid-`<think>` (`n_decoded = 2048` exactly), so the floor was raised 2048→4096 on 2026-08-19. Per-turn urlopen timeout is **420 s** (was 30 s → 240 s — reasoning `<think>` traces + max_tokens exceed 30 s at ~40–55 t/s and truncated turns; Ornith-1.5-9B agentic 0.2667 → 0.8000 after the 30→240 s fix; slow CPU-offloaded MoE rigs need up to 240 s per 2048-token turn, 420 s per 4096-token turn). **Observability:** per-run artifacts live in `autoresearch/runners/logs/` (gitignored, keep last 20): `llama-server-<UTC>-<model>.log` (rotated per Trial; the old shared `llama_server.log` was wiped every run) and `agentic-<UTC>-<model>.json` (per-task score/rubric/report-length/turns/`length_stops`/`http_errors`). HTTP 400/500 bodies are printed with the error; `finish_reason=length` (max_tokens exhausted) is counted per task. **`REASONING_PRESERVE`:** Baseline engine knob (`None` = template default; `True`/`False` = `--reasoning-preserve` / `--no-reasoning-preserve`). Seed from the card only when `GET /props` `chat_template_caps.supports_preserve_reasoning` is true — not a Search neighbor; coding-10 is single-shot. **Coding-10 sandbox:** `_run_subprocess` always uses a private temp `cwd` — BigCodeBench tasks (e.g. `files.zip`) and bad solutions must not write into the repo root.
- **Status recompute after every Trial write (issue #5)**: `run.py` / `autoloop.py` refresh the whole store's statuses after each write via `autoresearch/core/recompute.py` (pure, idempotent) so a new `on_front` point demotes rows it dominates to `dominated`. `scripts/recompute_status.py` runs the same refresh retroactively. Stored status is the global-by-hardware+budget front (ADR 0006); incomplete/rejected and fingerprint-less legacy rows never compete. **Budget bucket** = `round(VRAM_LIMIT_MB/1024)` from `config_json` (intended limit); peak `memory_gb` is legacy fallback only — same-Fingerprint Trials with different peaks must still merge.
- **Perplexity-Guided Tuning Guard**: When using `--perplexity-val` to maximize throughput (TPS), enforce a strict quality ceiling: any candidate configuration resulting in more than a 1% increase in perplexity (PPL) compared to the baseline must be discarded.
- **Single-load gate (issue #41)**: `autoresearch/core/single_load.py` refuses a second full server while one is live on a harness port (`SingleLoadError`, reuses the #37 detection surface). Wired into `LlamaServerRunner.__enter__` and `SGLangServerRunner.start` before the orphan sweep; a speculative draft on the same server never counts. Fail-open like the sweep: a detection failure logs and proceeds. Bypass via `AUTORESEARCH_ALLOW_MULTI_SERVERS=1` (also skips the sweep so a live sibling is not killed).
- **SGLang lifecycle + trust-remote-code**: the SGLang runner composes `PR_SET_PDEATHSIG` with its `os.setsid` preexec (no orphan on abrupt parent death) and escalates teardown terminate → grace → SIGKILL. `--trust-remote-code` is opt-out via `SGLANG_TRUST_REMOTE_CODE=0` (default on, matches legacy behavior) for non-self-curated checkpoints.
- **Results store + derived mirror**: `results.tsv` is the canonical Trial store (append-log; never hand-edited except documented gambiarra scripts). `autoresearch/core/results_db.py` maintains a derived SQLite mirror (`results.db`, gitignored) — refreshed by `recompute_statuses()` inside the results lock after every call (both rewrite and no-op paths), best-effort (`try_sync_from_tsv` never raises, so a mirror failure cannot affect a Trial). The mirror is a read cache: query it for fast indexed frontier/ranking lookups, never treat it as truth; force-rebuild + parity check via `scripts/rebuild_results_db.py`.
